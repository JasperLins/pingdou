# 执行计划 · px-creat-web P0（任务地图）

## 任务地图与依赖

```text
M0 工程基建 ──┬──> M1 lib 算法层 ──> M2 编辑器 MVP ──┬──> M3 三入口与生成类型
（先行）      │                                      ├──> M4 烫染预览集成
             └──────────────────────────────────────┴──> M5 导出三件套
                                                     M3/M4/M5 全部完成
                                                            │
                                                            v
                                                     M6 P0 质量验收
                                                            │
                                                            v
                                                     M7 P0 内 P1 批次（按反馈排内部优先级）
```

- M0 与 M1 可并行（M1 不依赖 UI 脚手架，仅要求仓库与 Vitest 就位）
- M2 是汇聚点：M3/M4/M5 都依赖 M2 的画布与状态管理
- M4 的烫染渲染算法在 M4 子任务内实现（本工作区无原型可平移）

## 子任务索引

功能粒度的模块视图（模块→功能→里程碑映射）见同目录 `features.md`。

| 子任务 | 交付物 | 验收门 |
| --- | --- | --- |
| m0-infra | 脚手架、Tailwind token、ui 组件起步、路由骨架、SEO 方案定稿 | tsc+build 过，营销页预渲染出静态 HTML |
| m1-lib | lib/ 六模块 + 色板 CSV 入库 + 单测 | 转换 104×104×291 色 ≤2s；单测过 |
| m2-editor | 画布/工具集/撤销/色板/用量/参考层/自动保存 | 绘制响应 ≤100ms，快捷键体系可用 |
| m3-entry-convert | 新建入口、生成类型预设、转图流程对照 | Q版/标准/写真预设联动正确 |
| m4-finish | 烫染 6 预设面板、Worker 渲染、finish 持久化、效果封面 | 切换 ≤1s 不冻结 UI，零副作用 |
| m5-export | 图纸 PNG / BOM CSV / 工程 JSON 导入导出 | 版式对齐样图，Q1/Q5/Q6 过 |
| m6-acceptance | 样图复刻全流程、性能实测、验收报告 | 父任务跨子任务验收标准全过 |
| m7-p1-batch | 对称/图层/数位板/工艺卡/分享图/分页打印 | 按反馈逐项独立验收 |

## 启动顺序建议

1. `task.py start` 于 **m0-infra**（或 M0/M1 双开，若并行开发）
2. 每个子任务完成 → 质量检查（trellis-check）→ 归档 → 启动下一个
3. 父任务不承载实现，仅在 M6 后做集成评审

## 回滚点

每个子任务独立分支/提交；工程 JSON schema 与色板数据结构是全局契约，变更需在父任务 prd.md 记录并通知所有未完成子任务。
