# PRD · px-creat-web Web 创作端 P0 开发（总任务）

## Goal

交付拼豆生态 P0 的 Web 创作端：创作者在浏览器内完成 画图 / 图片转图纸 → 精修编辑 → 烫染效果预览 → 导出三件套（图纸 PNG / BOM CSV / 工程 JSON）的全流程，产出与市面图库同规格的高质量图纸。技术底座为 React + TS 独立 SPA（Vite），SEO 通过营销页预渲染满足。

## 范围调整决议（相对需求文档）

1. 三入口合并："自由创作"与"导入作品"合并为一个入口（均进空白画布，区别仅为参考层是否预挂图）；"图片转图"独立入口保留。
2. 烫染预设 P0 交付 6 种：正常烫/毛巾烫/格利特烫/亮片烫/华夫格烫/搓澡巾烫（单面无孔/褶皱维持 P2）。
3. 埋点降级：仅做 `lib/analytics.ts` 本地匿名事件接口留位，不做面板、不上报。
4. P0 内 P1 项（对称/图层/数位板/三档模式/工艺卡 F5/分享图 F7/A4 分页打印）集中到 m7-p1-batch，按 M6 验收后的反馈排优先级，不阻塞 P0 交付。

## Requirements（跨子任务）

- 覆盖文档 §4.2 质量标准（Q1–Q6）、§4.3 三类入口与生成类型、§4.4 编辑器 P0 能力、§4.5 品牌色号系统（五品牌 1,386 色）、§4.6 烫染预览 F1–F4/F6、§4.7 导出三件套，按任务地图拆入子任务。
- 纯前端：P0 无账号、无后端依赖；部署轻、迭代快。
- lib/ 算法层（色彩科学/色板/转换/图纸导出/存储）为纯函数库，与 UI 解耦，可单测。
- 整站视觉以 web-style 双图为基准（大圆角卡片、pill 按钮、粉彩渐变、角色插画出血、贴纸元素），组件结构可参考 lineone，但配色/圆角/字体 token 不得沿用其 navy 后台风。

## Acceptance Criteria（P0 整体，对齐文档 §4.11）

- [ ] 工作流闭环：上传 → 转换 → 参考层微调 → 烫染预览 → 导出三件套，全程浏览器内完成
- [ ] 质量：样图复刻 Q1–Q6 全过（每格一色可追溯、无抖动、成簇、轮廓可读、版式一致、色彩还原）
- [ ] 性能：104×104 转换 ≤2s；绘制响应 ≤100ms；烫染单预设切换 ≤1s 不冻结 UI；自动保存 30s 不阻塞
- [ ] 工程：`tsc --noEmit` 零错误、生产构建通过、lib/ 核心管线有单测
- [ ] SEO：营销页预渲染产出静态 HTML，meta/OG 由路由层统一管理

## 明确排除（P1+ 承接）

登录注册与创作者认证、云端存储、图床上架与交易、BOM 对接豆权益购买、实拼验证流程、模板中心。
